# Design — Agape v1.1.0: the library layer

> Status: **draft / proposal** (not yet folded into SPEC.md). Branch: `spec/v1.1.0`, off
> `main` @ `bdaec64` (finalized v1.0.0 spec).
>
> This document is the design pass that must land *before* conformance tests and before any
> SPEC.md edit (doc → test → build). It proposes four additions that together make agape code
> packageable, importable, encapsulable, and abstract enough to express a reusable library —
> motivated by the planned cognition library, but general.

---

## 0. Why, and the one guarantee that shapes everything

v1.0.0 can *extend* (agents, subtractive grants) and *inject dependencies* (provider / tool /
principal bound by manifest), but it cannot **package** code: `program ::= decl*`, a single
`entry = "main.ag"`, one flat global namespace, no visibility, no user generics, no abstract
contract. A library today is copy-pasted source. (See the audit: gaps 1–6.)

**The headline design constraint:** v1.0.0 is in production and must not be disrupted, and the
Stability theorem (§15.5.5) and reproducibility guarantees (§15.6, T1–T5) must survive intact.
The way we honor both:

> **The entire library layer is a static / compile-time addition. The dynamic semantics
> (§15.4) — the spine, ticks, the oracle model, replay — are essentially untouched.**

- **Modules / imports** = a name-resolution + linking phase before type-checking. No runtime.
- **Generics** = monomorphized at compile time. Each instantiation is a distinct concrete type;
  the runtime never sees a type parameter.
- **Visibility** = static access control over *names*. The spine stays physically complete (a
  private event still lands on it for audit/replay); visibility only governs what source in
  another module may *name*.
- **Interfaces** = static agent subtyping. An interface-typed binding still resolves at runtime
  to a concrete agent address; a send to it is the same `E-Send`.

The only refinement that reaches the dynamic semantics is **event-type qualification**: the
spine's `etype` becomes a fully-qualified name (§4.2 below). That is a naming refinement, not a
new rule, and it is the one place §15.4 text changes.

**Backward compatibility (must hold):** every well-typed v1.0.0 program is a well-typed v1.1.0
program with identical `obs`. Achieved because (a) a file with no `module`/`import` is the
implicit **root module**, (b) unqualified names resolve within the current module + prelude as
today, and (c) default visibility is module-private — which is invisible in a single-module
program because everything is already in the same module.

---

## 1. Goals / non-goals

**Goals.** Multi-file projects; importable, versioned packages; collision-free namespacing;
declaration-level encapsulation that also closes the spine-vocabulary leak; user-defined
generics; an interface concept that makes "satisfies the agent interface" a *checkable* contract.

**Non-goals (v1.1.0).** A package *registry* / network fetch (path + git deps only for now);
**arbitrary** user subtype hierarchies (only single-level extension of the built-in `Error`
root is included — Feature E); re-opening §13 gate semantics (owned by another agent —
coordinate, do not touch); separate-compilation/ABI (monomorphization is whole-program for
now).

## 2. Feature A — modules, files, packages, imports

### 2.1 Concepts

- **Module** = one source file (`*.ag`). Its **module path** is its path relative to its
  package's source root, `.`-separated, without extension: `src/cognition/judge.ag`
  → `cognition.judge`.
- **Package** = a directory with an `agape.toml` carrying a `[package]` table and a library
  entry. The current project is itself a package (it already has `agape.toml`).
- **Prelude** = the implicit module `agape` (the §9 prelude: `Credence`, `Decision`,
  `Entailment`, `Error`, `Decided`, …), auto-imported unqualified into every module.

### 2.2 Grammar additions (against §15.2)

```
program    ::= moduledecl? import* decl*               // NEW: optional header + imports first
moduledecl ::= "module" modpath ";"                    // NEW; optional, defaults to file-derived path
import     ::= "import" modpath ("as" Ident)? ";"      // whole-module, optionally aliased
             | "import" "{" Ident ("," Ident)* "}" "from" modpath ";"   // selective
modpath    ::= Ident ("." Ident)*
```

`decl` is otherwise unchanged except for the `vis` prefix (Feature C) and the new `interface`
form (Feature D).

### 2.3 Resolution

- A bare `modpath` whose head is **the current package or a local sub-path** resolves to a file
  within the package source root.
- A `modpath` whose head names a **declared dependency** (manifest `[dependencies]`) resolves
  into that package's source root.
- Imports are acyclic (a `ModuleCycleError`); resolution is a static topological link step.
- Importing binds names into the current module's scope: whole-module `import cognition.judge;`
  binds the qualified prefix (`judge.Judge`), `as` rebinds the prefix, selective `import { Judge }
  from cognition.judge;` binds the bare name.

### 2.4 Manifest additions (§16.1)

```toml
[package]   name = "cognition"   version = "1.1.0"   lib = "src/lib.ag"

[dependencies]
cognition = { path = "../cognition" }                 # path dep
util      = { git = "…", rev = "…" }                  # pinned git dep (no registry yet)
```

- `entry` (the existing app entry) and `lib` (a package's importable root) coexist: an app has
  `entry`; a library has `lib`; a project may have both.
- **Reproducibility (§16.3):** a run is `(I, manifest, recording)`. Dependency resolution is
  pinned (path or rev), so the resolved source set is fixed and version-controlled, exactly like
  the backend bindings. No new nondeterminism.

## 3. Feature B — namespacing

### 3.1 Names

- Every top-level declaration has a **fully-qualified name** = `modpath . Ident`.
- Within its own module a name is used bare; from another module it is used via its imported
  prefix/alias or a selective bare import. Collisions across modules are resolved by
  qualification; an ambiguous bare reference is a `NameError`.
- The prelude namespace `agape.*` is auto-imported unqualified; a user module may shadow a
  prelude name only with an explicit local declaration (a `ShadowWarning`).

### 3.2 The spine etype is now qualified (the one dynamic-semantics touch)

§7 / §15.4: an event's `etype` becomes its fully-qualified name. Consequences:

- `when (cognition.Tick t)` matches only that module's `Tick`; a different module's `Tick`
  is a *distinct* spine type. This is what closes accidental cross-library `when`/`emit`
  aliasing.
- **Subtyping is unchanged and still cross-module:** the built-in hierarchy (`Error` ⊃
  `Contradiction`, `TypeMismatch`, …) lives in `agape.*`; `when (Error e)` still catches every
  built-in subtype regardless of which module appended it. (User-defined subtyping remains out
  of scope — §7 open question.)
- Canonical event serialization (the §16.5 chain-head hash) now serializes the qualified name.
  This **changes chain-head hashes vs v1.0.0** for the same program — acceptable across a minor
  spec bump, but call it out in the conformance migration notes.

## 4. Feature C — visibility

### 4.1 Rule

```
decl ::= vis? (typedecl | tool | agent | policy | fn | interface)
vis  ::= "pub"
```

- **Default = module-private.** A declaration with no `pub` is nameable only within its module.
- `pub` exports the name for import by other modules.
- Backward compatible: a v1.0.0 single-module program is one module, so private-by-default
  leaves every name mutually visible exactly as before.

### 4.2 What visibility governs — and what it does NOT

Visibility is **static name access**, not a runtime partition. The spine remains the complete
account (§7, §15.4.2a): a private `event`/`action` still physically lands on the spine and is
visible to audit tooling and replay. Visibility only controls what *source in another module may
name*:

- A private `event`/`action` type cannot be `emit`/`perform`/`when`-referenced from outside its
  module (W-Auth still applies on top; visibility gates the *name*, grants gate the *power*).
- A private `agent` type cannot be `spawn`ed, `reach`-granted, or `extend`ed from outside.
- A private `fn`/`struct`/`enum`/`policy`/`interface` cannot be referenced from outside.

This is exactly what closes the audit's spine-vocabulary leak: a library's internal Se/Si helper
agents and their event vocabulary become unnameable outside the library, while the spine still
records everything for the auditor.

### 4.3 Interactions

- **`extend` across modules** requires the parent be `pub`. Subtractive grants (W-Extend)
  unchanged.
- **`pub` is shallow:** exporting a struct does not export the *types of its fields* — a `pub
  struct` with a private field type is a `VisibilityError` (no leaking a private name through a
  public signature). Same for `pub fn` params/returns and `pub agent` constructor params.

## 5. Feature D — generics and interfaces (the §15-heavy tier)

> **SUPERSEDED in part — see SPEC §19.5 (authoritative).** Two simplifications were made after
> review: (1) **generics are `struct`/`fn` only, plain (no kind bounds)** — agents and interfaces
> are *not* generic (an agent is event-reactive; its parameterization lives in its `when`
> handlers' event types; a generic `agent`/`interface` is a `ParseError`); the `Judge<E: enum>`
> framing below is retired. (2) **interface members use `when EVENT decide RESULT`, not
> `handles A -> B`** — `->` is a `LexError` in agape (§2), so the arrow form was invalid. The
> subsections below are kept for rationale; where they conflict with §19.5, §19.5 wins.

> This tier concentrates the formal-semantics work. Generics are mechanical (monomorphization);
> interfaces add an agent-subtyping relation and are the genuinely novel part.

### 5.1 User generics

```
typarams ::= "<" typaram ("," typaram)* ">"
typaram  ::= Ident (":" kind)?              // optional kind bound
kind     ::= "enum" | "struct" | "agent" | "interface"
typeargs ::= "<" type ("," type)* ">"
```

- Add `typarams?` to `struct`, `fn`, `agent`, and `interface` declarations; add `typeargs?` to
  type references (`type ::= … | Ident typeargs?`).
- **Enums stay monomorphic** (a closed variant set; a generic enum has no clear meaning here) —
  open to revisit.
- **Kind bounds** let a parameter require a shape, which is what makes `Credence<E>` usable in
  library code: `agent Judge<E: enum>(…) { Credence<E> c = …; }` — `E` must be an enum so the
  `Credence<E>` slot is well-formed.
- **Monomorphization at compile time.** `Judge<Ticket>` and `Judge<Severity>` are two distinct
  concrete agent types. The runtime, the spine, and §15.4 never see a type variable — this is
  why generics cost the dynamic semantics nothing.
- Static rules (§15.3) generalize straightforwardly: a generic decl type-checks against its
  bounds; each instantiation substitutes and re-checks (or checks once under the bound, then
  instantiates — choose in the formal pass).

### 5.2 Interfaces — a checkable agent contract

The novel addition. An **interface** names an agent's external surface: the messages it handles
and the powers it requires.

```
interface   ::= "pub"? "interface" Ident typarams? "{" ifmember* "}"
ifmember    ::= "handles" type "->" type ";"     // a request → reply protocol element
              | "requires" cap ";"               // a capability the implementor must hold
```

- An interface is a **type** (usable wherever a type is, incl. bindings, params, `reach`
  targets) but is **not instantiable** (`spawn Cognition` is a `TypeError`).
- **Nominal conformance** (consistent with agape's "explicitly declared" philosophy, §3): an
  agent declares the interfaces it implements; the compiler checks coverage.

```
agent ::= "pub"? "agent" Ident typarams? params
          (":" modpath ("," modpath)*)?          // NEW: implemented interfaces
          grants? "{" abody* "}"
```

```agape
pub interface Cognition {
    handles Query -> Decision<Plan>;             // must answer a Query with a settled Decision<Plan>
    requires reach Engineer;
}

pub agent ProductManager : Cognition grants { perform Prioritize, reach Engineer } {
    when (Query q) { /* … → returns Decision<Plan> */ }   // checked against `handles`
}
```

- **Conformance check (static, new in §15.3):** for each `handles A -> B`, the agent must have a
  `when (A …)` handler whose committed reply type is `B`; for each `requires cap`, the agent's
  `grants` must include `cap`. Missing ⇒ `InterfaceError`.
- **Subtyping:** `ProductManager <: Cognition`. A binding/param/`reach` typed as the interface
  accepts any implementor. `reach Cognition` grants the power to send into *any* agent satisfying
  `Cognition` — capability over an abstract surface, which is what lets an orchestrator wire
  cognitions polymorphically.
- **Runtime is unchanged:** an interface-typed binding holds a concrete agent address; the send
  is the ordinary `E-Send`. Interfaces are erased after checking.

### 5.3 Why this finally types the cognition library

`Cognition` becomes a real contract; a `Judge<E: enum>` parameterizes over a role's enum; the
orchestrator holds `array<Cognition>` and fans out (`|>`) over heterogeneous minds — all
statically checked, zero runtime cost, and the trust-lattice export wall (a cognition exports
`settled`) still holds because `handles A -> B` requires `B` be the settled reply type.

## 5b. Feature E — minimal error subtyping

So a library may define typed faults that plug into the built-in `when (Error e)` catch-all,
without opening arbitrary user hierarchies.

```
typedecl ::= …
           | "event" Ident "(" field ("," field)* ")" (":" "Error")? ";"   // optional Error supertype
           | "action" Ident "(" field ("," field)* ")" ";"                  // unchanged; no supertype
```

- **Only `event` may extend, and the only permitted supertype is the built-in `Error` root**
  (single level — no user-defined intermediate supertypes in v1.1.0). `action` is performative
  and stays non-error. A supertype other than `Error` is a `TypeError`.
- **`when` matching is already by subtype (§15.4):** declaring `pub event PaymentFailed(reason:
  text) : Error;` makes `when (Error e)` catch it, alongside the built-ins (`Contradiction`,
  `TypeMismatch`, …). The change is only that the subtype DAG gains user *leaves* under `Error`.
- **Visibility interaction (consistent with Feature C):** `when (Error e)` in another module
  catches a *private* user error by its built-in supertype — because it matches `Error`
  (prelude), not the private name. You can react to it as an `Error`, but cannot match it by its
  private `PaymentFailed` name without it being `pub` and imported. The event still lands on the
  spine for audit either way.
- **Formal touch:** §9 (hierarchy gains user leaves), §15.3 (well-formedness: a declared
  supertype must be `Error`), §15.4 (no new rule — subtype matching already covers it). Chain-head
  serialization is unaffected beyond the etype-qualification of Feature B.

## 6. Formal-semantics impact map (§15) — for the coordination conversation

| addition | §15.2 grammar | §15.3 static | §15.4 dynamic | Stability/§15.6 |
| --- | --- | --- | --- | --- |
| modules / imports | +`module`,`import` | + resolution/link phase, scoping | none | none |
| namespacing | qualified names | name lookup over qualified+prelude | **etype qualified** (only touch) | chain-head serializes qualified name |
| visibility | +`pub` | + access rules, shallow-export check | none (spine still complete) | none |
| generics | +typarams/typeargs | + bounds, monomorphization | none (erased) | none |
| interfaces | +`interface`, agent `:` list | + nominal conformance, agent subtyping | none (erased) | none |
| error subtyping | +`:Error` on `event` | + supertype-is-`Error` check | none (subtype match exists) | none |

Net: five of six additions are pure §15.2+§15.3. The lone §15.4 touch is etype qualification,
which also shifts chain-head hashes for the same source (a stated migration consequence, not a
semantic weakening). T1–T5 re-discharge with the qualifier carried through; no proof is broken.

## 7. Resolved decisions (2026-06-26)

All six finalized; the draft is locked for the test phase.

1. **Module granularity → file.** One `.ag` file = one module. Directory-merged namespaces may
   be added later, non-breakingly.
2. **Interface conformance → nominal.** An agent declares `agent PM : Cognition`; the compiler
   checks handler/grant coverage. Matches agape's explicit-declaration philosophy; clear errors.
3. **Error subtyping → include minimal (Feature E).** `event Foo(..) : Error;` may extend the
   built-in `Error` root, single level only; `action` stays non-error. Arbitrary hierarchies and
   user intermediate supertypes remain out of scope.
4. **Generic enums → excluded.** Enums stay monomorphic.
5. **`handles A -> B` → minimal.** Request→reply pair only; no session/multi-message protocols
   in v1.1.0.
6. **Monomorphization → whole-program.** Separate compilation deferred until a binary registry
   exists.
